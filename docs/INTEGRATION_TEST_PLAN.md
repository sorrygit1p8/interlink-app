# 실제 연결 후 통합·보안 검증 계획

이 문서는 **수행할 검증**이다. 데모 역할 전환, 모의 SDK 응답, SQL 소스 점검은 실제 인증·RLS·동시성·Realtime 검증을 대체하지 않는다. 원격 운영 서버는 이번 구현에서 연결하지 않는다. 실행 결과는 `TEST_REPORT.md`에 별도로 기록한다.

## 실행 전 조건

1. 새 계정·유료 자원을 자동 생성하지 않는다. 사용자가 후속 연결을 승인하면 소유한 격리된 staging 프로젝트 또는 로컬 Supabase를 사용한다.
2. 마이그레이션과 함수·버킷·Realtime 설정을 적용한다. 운영 DB에 테스트 시드를 적용하지 않는다.
3. 가상 테스트 사용자 A(팀장), B(지원자), C(초대받는 사용자), D(다른 커뮤니티), S(정지), O(운영자)를 만든다. 실제 학생 정보는 사용하지 않는다.
4. A/B/C의 인증 토큰은 각각 실제 Auth 세션에서 얻는다. 일반 동작 테스트는 공개 publishable/anon 키와 해당 사용자 세션만 사용한다. 관리자 키는 fixture 준비·정리 외의 권한 검증에 사용하지 않는다.
5. O는 서버 역할과 추가 인증(AAL2)을 갖춘 별도 세션으로 검증한다. 테스트 토큰·메일·메시지 본문을 로그에 남기지 않는다.

## 인증과 범위

| --- | --- |
| 실제 이메일 OTP 요청·잘못된 코드·만료·재전송 제한·네트워크 실패 | 실제 제공자 오류를 안전한 메시지로 표시, 가짜 로그인·데모 자동 전환 없음 |

| 다른 사용자의 신청서·신고자·기기 토큰·개인 계정 정보 조회 | 노출 없음; 공개 프로필에는 이메일 없음 |

## 팀 구성·동시성

1. A가 총 정원 2인 프로젝트를 만들면 팀장 포함 멤버 수는 1이다.
2. B가 신청한 뒤 A가 승인하면 신청 승인, 활성 멤버십, 채팅 접근, 알림/작업이 함께 생긴다. 중간 오류 시 전체 트랜잭션이 롤백되어야 한다.
3. 같은 멱등성 키로 승인 재시도 시 멤버·알림·작업이 중복되지 않아야 한다. 다른 사용자가 같은 키를 사용해도 다른 사용자의 결과를 읽을 수 없어야 한다.
4. 정원 2인 새 프로젝트에서 B의 신청 승인과 C의 초대 수락을 서로 다른 연결로 동시에 수행한다. 하나만 성공하고 나머지는 `FULL` 또는 충돌 오류, 최종 활성 멤버 수는 2여야 한다.
5. 순차 테스트로 동시성 통과를 주장하지 않는다. DB 트랜잭션/별도 인증 연결을 실제로 겹치게 실행하고 여러 번 반복한다.
6. 본인 신청·중복 신청·교차 신청/초대·마감·차단·정지·보관 프로젝트를 각각 검증한다. 초대 발송만으로 정원을 예약하거나 멤버를 추가하지 않는다.
7. 소유권 이전 후 이전 팀장의 관리자 권한 소멸과 새 팀장의 권한 획득을 확인한다. 팀장은 이전 또는 팀 종료 전 탈퇴할 수 없어야 한다.

## Storage·푸시·작업

- 타인 경로 객체 조회·덮어쓰기·삭제를 공개 키 + 일반 세션으로 시도해 거절을 확인한다.
- 확장자만 이미지인 실행/HTML/SVG 파일, 잘못된 magic bytes, 제한 초과 파일·크기, 변조 MIME를 거절해야 한다. 허용 이미지의 정규화·메타데이터 제거를 확인한다.
- 비공개 이미지의 서명 URL 만료를 확인한다. 이미 발급된 URL은 만료 전 즉시 철회되지 않을 수 있음을 운영 정책과 일치시킨다.
- 실제 iOS/Android 기기 권한 허용·거부, 토큰 갱신·로그아웃 해제, 무효 토큰 응답, Expo ticket/receipt 오류를 확인한다.
- 발송 직전 수신자 상태·멤버십·차단·선호·기기 활성 여부를 다시 확인한다. 잠금 화면에 채팅 본문이 노출되지 않아야 한다.
- 처리기 중단/재시작, 잠금 만료, 일시 장애, 최대 재시도, 영구 실패를 주입하고 작업 상태·다음 시도·운영 표시를 확인한다. 티켓 수락과 기기 도달은 별개다.
- 계정 삭제 중 Storage 또는 Auth 삭제를 실패시키고 재시도 후 정리 완료를 확인한다. 요청·처리 중·실패·완료는 구분하고 Auth 삭제 전 완료로 표시하지 않는다.

## 운영·실기기

- 일반 사용자, 운영자 역할만 있는 AAL1 세션, 유효한 AAL2 운영자 세션을 나눠 운영 API를 호출한다.
- 신고 관련 콘텐츠만 조회 가능하고 민감한 조회·조치에 메모·감사 기록이 남는지 확인한다. 임의 팀 채팅 열람 경로를 만들지 않는다.
- 차단 후 추천·신청·초대·관련 알림 제한을 확인한다. 이미 공유하는 팀 대화는 정책대로 유지/종료하며 완전한 분리처럼 안내하지 않는다.
- 실제 기기에서 안전 영역, 키보드, 작은 화면, 큰 글씨, 화면 읽기, Android 뒤로가기, 딥링크 접근 재검증, 오프라인 재전송을 확인한다.
- 백업/복구와 제한된 부하·지연·오류 테스트는 개인정보 없는 staging 데이터에서 측정한다. 측정 전 수치를 기록하지 않는다.

실행 증거에는 명령, UTC 또는 Asia/Seoul 시각, git 커밋, 환경/데이터 모드, 테스트 세션 역할(토큰 제외), 결과 로그 경로를 남긴다. 실제 메일·푸시·기기 설치·스토어 제출 여부는 각각 구분한다.
