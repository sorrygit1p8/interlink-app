# 인터링크 구조와 신뢰 경계

인터링크는 승인된 학생 커뮤니티 안에서 프로젝트 발견 → 신청 또는 초대 → 상호 동의에 따른 팀 구성 → 팀 채팅 → 경험 기록을 연결한다. 공개 출시 전 연동 준비 버전이며 외부 운영 서버는 현재 연결하지 않는다.

## 구성

- `apps/mobile`: Expo, React Native, Expo Router 기반 Android/iOS 앱과 웹 미리보기. 웹 미리보기는 네이티브 설치 검증이 아니다.
- `apps/web`: Next.js 운영 웹, 정책 초안과 계정 삭제 요청. 실제 운영 경로는 서버에서 세션·역할·추가 인증을 확인한다.
- `packages/shared`: 입력 검증, 도메인 타입, 상태, 안정된 오류 코드, 질의/명령 계약.
- `packages/data`: 동일 계약을 구현하는 데모 저장소와 Supabase 어댑터. 인증·세션·구독·업로드·푸시 연결 코드.
- `supabase`: 테이블, 제약, RLS, RPC 트랜잭션, 서버 함수와 내구성 있는 작업 처리 코드.
- `tests`, `supabase/tests`: 로컬 단위·모의 계약·브라우저 동선과 실제 DB 적용 후 검증 코드.

## 모드와 데이터

`development | staging | production`은 배포 환경이고 `demo | supabase`는 데이터 모드다. 데모에는 실제 인증이 없고 A/B/C 가상 인물을 명시적으로 선택한다. 로컬 시뮬레이션과 실제 사용자 세션은 같은 것으로 취급하지 않는다. 데모 진입은 이메일·푸시·원격 업로드를 호출하지 않는다.

Supabase 모드는 필수 설정이 없으면 실패하며 자동 데모 전환을 하지 않는다. 프로덕션은 데모를 거절한다. 사용자 변경·로그아웃·모드 변경 시 캐시와 구독을 정리하고 데모 데이터/실제 세션을 분리한다. 모드별 실제 저장 위치와 초기화 절차는 `ENVIRONMENT_SETUP.md` 및 앱의 모드 설명을 따른다.

## API와 권한

클라이언트는 `query(operation, input)`과 `command(operation, input, idempotencyKey)`를 사용한다. Supabase는 `interlink_query`와 `interlink_command` RPC로 연결한다. 응답은 camelCase이며 서버에서 정한 공개 필드만 전달한다. 목록은 커서 기반 페이지 응답이다.

프로필 공개 정보와 계정 비공개 정보는 분리한다. 실제 권한은 Auth 주체, 커뮤니티 접근, 활성 계정, 차단 관계, 소유권과 멤버십으로 결정한다. 클라이언트 역할 선택이나 입력한 `userId`가 인증이 되지 않는다. 직접 REST로 승인·멤버 추가·운영 조치를 우회하지 못하도록 DB 쓰기 권한과 RLS를 적용한다.

정원은 팀장을 포함한다. 승인/초대 수락은 프로젝트 행 잠금 안에서 상태 변경·정원 검증·멤버십·알림/작업을 묶는다. 초대는 정원 예약이 아니다. 멱등성 키는 재시도 중복 방지에 사용하며 다른 사용자의 요청 결과를 노출하지 않아야 한다.

## 실시간과 비동기 작업

DB가 원본이고 실시간 알림은 재조회의 신호다. 최초 구독 준비, 스냅샷 조회, 이벤트 병합과 재접속 후 재조회를 통해 누락을 복구한다. 실제 접근권은 서버에서 매번 확인하며 클라이언트 구독 해제를 보안 경계로 삼지 않는다. 이벤트에 비공개 본문이나 삭제 전 내용을 불필요하게 싣지 않는다.

구독 준비와 최초 조회의 경합을 막는 취소·재조회 순서, 이벤트별 질의 대응, Postgres Changes와 Broadcast·Presence의 권한 차이 및 공식 근거는 [실시간 복구 계약](REALTIME_CONTRACT.md)에 정리한다.

푸시·계정 삭제는 영속 작업으로 처리한다. 작업 획득/잠금, 시도 횟수, 다음 실행 시각, 오류 분류와 실패 상태를 저장한다. 푸시는 발송 직전에 계정·기기·선호·접근을 확인하고 Expo 영수증으로 무효 토큰을 비활성화한다. 삭제는 계정 접근 차단부터 시작하고 데이터·파일·외부 Auth 삭제의 부분 실패를 재시도한다.

## 검증의 경계

데모 테스트는 상태 전이를 검증한다. 모의 SDK 계약 테스트는 요청 형식·오류 처리·재시도를 검증한다. 소스 검사만으로 RLS, 실제 세션, 동시성, 실시간 권한 철회 또는 기기 푸시가 통과했다고 판단하지 않는다. 실제 결과는 `TEST_REPORT.md`, 후속 검증은 `INTEGRATION_TEST_PLAN.md`에 구분한다.
